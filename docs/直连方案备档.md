## 0. 一句话

把鱼的大脑从 ZCode automation 会话搬进适配器进程：**消息到达 → 直接调模型 API（无工具、纯文本）→ 写 outbox**。事件驱动、秒级响应、无消息零成本。

## 1. 架构对比

```
现状（automation 轮询）：
  QQ → NapCat → 适配器 → inbox
  → [cron 每5分钟] ZCode 新会话（框架注入 + agentic loop 6~7 次请求）
  → outbox → 出站链路 → QQ        空轮也烧钱

方案 A（事件驱动）：
  QQ → NapCat → 适配器 → inbox → 立即触发
  → brain.mjs 直调 API（1 次请求，无框架无工具）
  → 解析 JSON → 写 outbox + 记忆文件
  → 出站链路（审计/限额/分条全复用）→ QQ     无消息 = 0 成本
```

| 指标 | automation 轮询（现状） | 直连 |
|---|---|---|
| 空转轮成本 | ≈0.07 元 × 288 轮/天 | **0**（本地读索引判断，无消息不调 API） |
| 消息轮成本 | ≈0.08 元 | **≈0.008 元** |
| 月成本（24h 在线） | ≈¥600 | **≈¥35~60（省 92%+）** |
| 响应延迟 | ≤5 分钟 | **秒级** |
| 人格与记忆 | persona + 记忆文件注入 | 相同内容，脚本拼接 |

## 2. 为什么这么省（实测依据）

- **工具 schema 占 93%**：每轮会话前缀 ≈2.9 万 tok，大头是 57 个工具定义（内置 32 + 插件 MCP 26 + 挂件 4）——直连一次裸调用，全部砍掉
- **冷启动税**：每轮 automation 都是全新会话，首请求缓存命中 0（前缀含易变内容 / 轮询间隔超过缓存窗口）≈0.023 元/轮，占空转轮成本 1/3
- **尝试过砍插件 MCP 瘦身前缀**：workspace / user 级配置文件覆盖全线无效（桌面版对插件 MCP 是 app 级托管，Settings 的 MCP UI 才是管理面）
- **顺带证伪一条省钱歧路**：automation 内"复用会话"是负优化——对话历史每轮累积，且在每轮 6~7 次请求里按缓存命中价反复重付，历史攒到 5 万 tok 时单轮反贵 54%；止损需频繁 compact（本身一次全量大 miss 且时机不可控）。不要走这条路

## 3. 施工要点（约半天，~200 行）

1. **配置**：`config.json` 加 `brain` 段（provider / model / apiKey / baseUrl / debounceMs）——**key 放在 fishpond 之外**，鱼不可达，与 accessToken 同级红线
2. **brain.mjs（~150 行）**：读 inbox 索引 → 拼人格 + 记忆 + 报文（边界标记与不可信声明照做）→ 单次 API 调用（`response_format: json_object`）→ 解析 `{replies, silent, candidates}` → 交给现有出站链路；解析失败降温重试一次，再失败记日志放弃（**宁沉默不胡说**）
3. **触发器（~30 行）**：写完 inbox 后去抖触发（默认 90 秒，合并密集消息一次处理）；处理期间新到消息由收尾复查 pending 补跑
4. **automation 处置**：信箱任务**暂停不删**（它是回退通道）；learner 学习任务与聊天链路无关，保留不动
5. **回退**：`brain.enabled=false` + 重启适配器 + 恢复信箱 automation——一条开关，5 分钟回到现状

## 4. 安全面变化（相对现状）

| 变化 | 说明 |
|---|---|
| **变强** | LLM 无任何工具 → 文件操作攻击面归零；"诱导模型调工具"整类攻击不存在（比 guard 白名单更强的隔离） |
| **持平** | 出站审计正则 / [SILENT] / 三类限额 / 分条全在出站链路下游，一行不改；报文仍以边界标记声明为不可信数据 |
| **新增** | ① API key 落盘明文（与现有 accessToken 同级暴露，本机单用户 + 鱼不可达，可随时吊销轮换）② 直调不经 ZCode provider，平台用量视图看不到（按平台余额差值记账可补）③ brain 单点 bug = 鱼哑（解析失败不硬发 + automation 回退通道兜底） |
